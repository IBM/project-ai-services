## What's New

### 🔢 Embedding Service (Fixes #1467)

A new standalone service converts text and images into high-dimensional
vectors using an OpenAI-compatible API, running CPU-only on IBM Power
(ppc64le). No Spyre accelerator card is required.

- **OpenAI-compatible API** — `POST /v1/embeddings` accepts text strings
  and returns float32 vectors; drop-in replacement for existing clients
- **12 supported models** — multimodal (CLIP), multilingual text
  (Granite 278M), image-only (ResNet-18/50/101, ViT, BEiT families)
- **CPU-only** — runs on standard IBM Power LPARs; no GPU or Spyre card
  needed; ~6 GB RAM, 16 CPU cores, 2 GB model storage
- **Both runtimes** — deployable via `ai-services` CLI on Podman
  (ppc64le) and OpenShift
- **Oracle integration** — callable from Oracle PL/SQL via `UTL_HTTP`
  for direct vector storage in Oracle 23ai

|---|---|---|
| `openai/clip-vit-base-patch32` | Image + Text | 512 |

## Internal / Development Changes

<details>
<summary>Expand for developer-facing changes</summary>

- Embedding service follows the same layered image pattern as other
  services: `service-base` → `embedding-service`
- `APPROVED_EMBEDDING_MODELS.json` governs model availability; set
  `enabled: false` to remove a model without deleting its audit record
- `values.schema.json` provides a rich model dropdown in the Catalog UI
  with per-model descriptions for Podman; OpenShift schema is minimal
- Unit tests run in the shared `service-unit-tests` CI workflow
  alongside all other service tests

</details>
