# Release Notes — v0.4.0

> **IBM Power AI Launchpad** · [Documentation](https://www.ibm.com/docs/en/aiservices/2026.09.0) · [Migration Guide](https://www.ibm.com/docs/en/aiservices/2026.09.0?topic=launchpad-migration-guide-v032-v040)

---

## What's New

### 🔀 Translation Service

A new standalone service translates documents and free text between languages using the configured LLM backend.

- **Synchronous endpoint** — `POST /v1/translate` for stateless, single-request translations
- **Asynchronous jobs** — submit `.txt` or `.md` files via `POST /v1/translate/jobs`; poll for status and download the result when ready
- Token-based chunking with a context-window guard prevents oversized inputs from reaching the model
- Language detection is handled automatically via Lingua; language codes are validated before dispatch

---

### 🧩 Extract Service

A new structured-data extraction service turns unstructured documents into typed JSON records.

- Synchronous (`POST /v1/extract`) and asynchronous (`POST /v1/extract/jobs`) endpoints
- Accepts a JSON schema example as part of the request to guide extraction
- Batch file handling for the async endpoint
- Background worker processes async jobs independently of the request lifecycle
- OpenShift and Podman manifests included

---

### 🔌 Data Source Connectors

Services can now pull documents directly from external data sources on a schedule.

- Create, update, and delete connectors via the dedicated `/v1/connectors` API
- **Incremental sync** — only new or changed files are ingested on each background sync cycle; a manual sync can be triggered at any time
- Sync history is queryable per connector; in-progress syncs can be cancelled
- Connector secrets are encrypted at rest with AES-256-GCM before DB insert
- The deploy flow includes a dedicated data source connector step in the UI

---

### 👷 Remote Workers

Compute resources on separate hosts or clusters can now be registered with the catalog and used for deployments.

- **Auto-registration** — the catalog host (running on Podman or OpenShift) registers itself as a local worker automatically on configure
- **Remote worker registration** — run `ai-services catalog worker register` on the catalog to register a remote worker; use `catalog worker deregister` to remove it
- **Worker join** — run `ai-services worker join` on the remote machine to connect it to the catalog
- **gRPC gateway with mTLS** — the catalog exposes a gRPC gateway server for worker communication; workers exchange a one-time token for a CA-signed client certificate, and all subsequent `CommandStream` connections are mutually authenticated and encrypted
- Worker resources and runtime selection are integrated into the deploy flows; namespace and worker name appear in `application ps` output

---

### 🏷️ Bring Your Own Service (BYOS)

Operators can now package and register custom service components with the catalog.

- Upload a bundle (`POST /api/v1/bundles`), validate it, and reload catalog items — all via CLI or API
- Full CRUD lifecycle: list, get, replace, and delete bundles
- `ai-services catalog bundle` CLI commands included
- Application template support for custom BYOS components

---

### 🖥️ Catalog on OpenShift

The `ai-services catalog` command set is now fully operational on OpenShift.

- `catalog configure`, `catalog uninstall`, `catalog info`, `catalog login`, and password reset all work against an OpenShift cluster
- Application lifecycle: create, list, ps, delete, and resources APIs for OpenShift runtime
- All OpenShift-specific commands have been migrated to the unified catalog path
- RBAC for catalog and worker pods on OpenShift is correctly scoped

---

### 🌐 Japanese Language Support

Japanese is now supported for Digital Assistant.

- Document ingestion and Q&A will accept Japanese-language content
- spaCy sentence splitter handles Japanese tokenisation; `ja_core_news_sm` is bundled in the service image

---

### 🔌 MCP Sidecar Support

An MCP sidecar is now available for the **Summarize**, **Similarity**, **Q&A**, and **Digitize** services, exposing each service's API as MCP tools.

## Improvements

### Document Processing
- **Duplicate detection** — files are hashed (SHA-256) on ingest; exact duplicates are rejected with `409` or flagged per-file in mixed batches; duplicate file names are surfaced in the document `GET` response
- **Job cancellation** — `POST /{job_id}/cancel` stops an in-flight digitize or ingest job at the next safe checkpoint; `CANCEL_PENDING` and `CANCELLED` statuses added; cancellation propagates into the conversion, processing, chunking, and indexing stages
- **Conversion concurrency** — a Postgres-backed global conversion queue caps concurrent `convert_doc()` calls and is durable across restarts

### AI Services UI
- Rebranded to **IBM Power AI Launchpad**
- Two new tabs added: **Connectors** for managing data source connectors, and **Worker Resources** for viewing registered workers
- Session timeout: users are warned 2 minutes before automatic logout after 15 minutes of inactivity; background token refresh keeps active sessions alive
- Worker details (namespace, worker name) visible in the Digital Assistant and Services tables
- Model-first selection for Digital Assistant global component dropdowns
- Version strings are now prefixed with `v` throughout the UI

### CLI
- `ai-services must-gather` collects diagnostic information from Podman and OpenShift deployments for support and troubleshooting
- `application create` now accepts a `--worker` flag to target a specific remote worker for deployment
- The `--runtime` flag has been removed from most commands; it remains required only where the runtime cannot be inferred
- `--legacy` flag is no longer required for `image`, `model`, and `templates` commands
- Minor output formatting and help-text improvements

### LLM / Model Support
- Granite 4.1
- vLLM CPU image updated to v0.28.0 on Podman and OpenShift
- LiteLLM bumped to v1.101.0 on both Podman and OpenShift runtimes
- RHAII image updated to v3.5.0

### Authentication
- ManageIQ token passthrough: `POST /api/v1/auth/token` exchanges a ManageIQ token for a catalog API JWT pair
- IAM JWT validation replaced with Bearer token passthrough
- Password prompted for OpenShift catalog deployment; password reset command also supported

### Security
- Critical SSRF vulnerability in the Swagger UI endpoint addressed
- Multiple Go stdlib, `oras-go`, `golang.org/x/text`, `cryptography`, `Pillow`, `proxy-addr`, and npm CVE fixes

## Breaking Changes

> ⚠️ **Upgrading from v0.3.0?** Follow the [Migration Guide](https://www.ibm.com/docs/en/aiservices/2026.09.0?topic=launchpad-migration-guide-v032-v040) before deploying.

- **Summarize is no longer part of the Digital Assistant** — it must be deployed as a standalone service.
- **Worker join is now required for remote deployments** — the catalog configure step auto-joins the local host as a worker; remote hosts need to run `worker join` before deploying applications.
